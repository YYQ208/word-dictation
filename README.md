# 单词默写小助手

给孩子用的**听音默写**网页：电脑或平板报读音，孩子在纸上写，全程不需要家长念。

- **在线使用**：<https://yyq208.github.io/word-dictation/>
- **英语 / 语文双模式**：听英文写单词、听中文写单词；语文模式听词语写词语
- **单文件、零依赖**：就是一个 `index.html`，没有任何 CDN、字体、图片，断网也能用
- **数据不出本机**：所有词表只存在自己浏览器的 localStorage 里，不上传任何服务器

## 快速开始

**方式一：直接用**

打开 <https://yyq208.github.io/word-dictation/>，推荐在 iPad / 手机上用 Safari 或 Chrome 打开后选「添加到主屏幕」，会得到一个独立图标，用起来和 App 一样。

**方式二：本地使用**

把 `index.html` 下载到任意目录，双击用浏览器打开即可，不需要装任何东西，也不需要联网。

> 浏览器要求：Chrome / Edge / Safari 任一较新版本。语音由系统语音引擎（Web Speech API）提供，Windows 若没声音，需要先在「设置 → 时间和语言 → 语音」里安装英语 / 中文语音包。

## 功能一览

| 功能 | 英语模式 | 语文模式 |
|---|---|---|
| 播报内容 | 听英文发音 / 听中文释义 | 只报词语 / 词语＋提示语 |
| 词条格式 | `英文 中文释义` | `词语`、`词语 = 提示语` |
| 批量输入 | 一行一条 | 一行一条，或用顿号 / 逗号 / 分号隔开 |
| 多音字校正 | — | ✅ 内置词表 + 拼音注释 |

两套模式的数据**互不干扰**：英语的列表、语文的列表、各自的播报设置都是分开保存的，切换模式不会互相污染。

## 输入格式

### 英语模式

一行一条，英文在前，中文释义在后（中文可省略）：

```
apple 苹果
look at 看一看
What is your name? 你叫什么名字？
```

支持三种形式：

| 写法 | 含义 |
|---|---|
| `apple` | 只有英文，报读音写单词 |
| `apple 苹果` | 英文 + 释义，可切换成「听中文写英文」 |
| `you're=you are 你是` | `=` 前是缩写、后是完整形式，朗读时会念成两段（中间停顿） |

单词、词组、句子都支持，程序会自动判断类型并套用对应的播报参数。纯英文行也可以用逗号 / 顿号并列多个单词，如 `apple, banana, pear`。

### 语文模式

**方式一：一行一个**

```
葡萄
观察
拼命
```

**方式二：用顿号 / 逗号 / 分号写在一行**

```
葡萄、观察、拼命
```

顿号 `、`、中文逗号 `，`、英文逗号 `,`、中文分号 `；`、英文分号 `;` 都可以，连续或末尾多余的分隔符会自动忽略，两种方式也能混着写。

> ⚠️ 只有**不含 `=`** 的行才会按顿号拆分。带提示语的行整行保留，因为例句里本来就可能出现顿号。

**带提示语**

```
拼命 = 他拼命地向前跑
```

提示语会在词语之后再播一遍，帮孩子确定是哪个字。适合同音字多、光听词语分不清的情况。

**多音字处理**

浏览器语音接口不支持标注读音，所以提供了两层方案：

1. **自动校正（默认开启）**：内置约 95 个小学高频多音字词，朗读时自动换成同音字，屏幕显示仍是原词。例如 `银行` 会被念作 yín háng、`重新` 念作 chóng xīn。可在「播报设置 → 多音字校正」里整体关闭。
2. **手动指定（精确兜底）**：在词条后用括号写拼音，全角半角括号都认，带声调符号或数字声调都行：

   ```
   长（zhǎng）
   出差（chu1 chai1）
   长(zhang3) = 长大的长
   ```

   这条优先级高于自动校正，写一次就随列表一起保存。

> 单字条目（如只写「长」）没有语境，任何语音引擎都只会念最高频读音，这种情况必须用拼音注释。

## 播报设置

| 设置项 | 说明 |
|---|---|
| 播报内容 | 英语：英文 / 中文；语文：只报词语 / 词语＋提示语 |
| 多音字校正 | 仅语文模式显示，默认开启 |
| 播报顺序 | 顺序 / 随机 |
| 每个单词重复 | 1 / 2 / 3 遍 |
| 重复间隔 | 同一词两次朗读之间停多久，默认 2 秒 |
| 单词间隔 | 换到下一个词之前停多久，默认 5 秒 |
| 语速 | 0.5～1.2 共 8 档，默认 0.8（标准） |

设置会按词条类型分别记忆：单词、词组、句子各有一套，切换列表时自动套用。比如「单词」设 3 秒间隔、「句子」设 10 秒，切到哪种类型就用哪套。

## 默写过程中

- **进度条**显示第几个 / 共几个
- **👀 按住看单词**：按住才显示答案，松手隐藏，用于卡住时偷看
- **⏮ 上一个 / ⏭ 下一个**：手动跳转，会自动停止当前朗读
- **🔁 再读一遍**：重播当前词
- **⏸ 暂停 / 继续**：正在发声时冻结音频，等待间隔时保留剩余时间，继续后不会从头重播，也不会把间隔重新计一遍
- **✕ 结束本次默写**：中途退出

默写结束后会按**实际播报顺序**列出全部词条，方便对照批改。

## 列表管理与备份

- **保存列表**：输入内容后起个名字保存，同名时会弹窗让你选「覆盖 / 合并 / 改名」
- **自动分组**：列表名里带年级、册别、Unit（如 `三年级上册U1`、`第3课`）会自动排序并分组
- **搜索**：列表多了以后可按名字搜索
- **导出 / 导入**：一键导出全部列表为 `.json`，发到手机或另一台电脑后导入即可恢复，用于跨设备迁移和备份

> 导入时若遇到同名列表，会先询问一次：确定 = 合并（保留原有词条、追加新词），取消 = 跳过这些同名列表。

## 数据与隐私

**没有任何网络请求**，词表、设置、进度全部存在浏览器 localStorage 中：

| 键 | 内容 |
|---|---|
| `dictation_lists_v1` | 英语列表 |
| `dictation_lists_zh_v1` | 语文列表 |
| `dictation_settings_v1` / `dictation_settings_zh_v1` | 两套播报设置 |
| `dictation_type_settings_v1` / `_zh_v1` | 按词条类型分别记忆的设置 |
| `dictation_mode_v1` | 上次使用的模式 |

由此带来两个必须知道的后果：

1. **换设备 / 换浏览器，数据不会自动同步**，需要用「导出 → 导入」迁移。
2. **清除浏览器数据会清空所有列表**，建议定期导出备份。

浏览器存储配额约为 5MB，几千个词条远用不到上限；一旦写入失败，页面会明确提示而不是静默丢失。

## 技术说明

- **形态**：单个 `index.html`，约 2,300 行，HTML + CSS + 原生 JS（ES5 风格，IIFE 封装），无构建、无框架、无依赖。
- **语音**：Web Speech API（`speechSynthesis`）。代码里做了一层看门狗：
  - 延迟 50ms 再播放，规避 `cancel()` 与 `speak()` 的竞态；
  - 每 150ms 轮询，发现合成器被浏览器挂起时自动 `resume()`；
  - 1.2 秒内没开口就切换候选语音（Google 联网语音在国内会无声挂起）；
  - 用「世代号」让过期回调失效，避免快速切词时旧词重新播放。
- **多音字校正**：浏览器不支持 SSML 的 `<phoneme>`，无法指定单字读音，因此改用「同音字替换」——把要朗读的文本换成读音相同的别字再交给引擎，显示文本保持原样。数据为「95 条词级映射 + 1064 个音节到候选同音字 + 1287 字多音字集合」，由 pypinyin + jieba 词频离线生成后人工校对，判据是「目标读音 ≠ 该字在真实词语中的主导读音时才替换」。
- **无障碍**：保留了双指缩放能力；双击缩放被 `touch-action: manipulation` 禁用（避免误触放大且无法还原）。

## 常见问题

**Q：点了开始但没声音？**

先确认设备有没有对应语言的语音引擎。Windows：设置 → 时间和语言 → 语音 → 添加语音包。手机一般自带。页面检测不到引擎时会弹提示。

**Q：某个词读音还是错的？**

自动校正表只收录了高频词。用拼音注释写一次即可，例如 `重要（zhòng yào）`，会随列表保存。

**Q：手机上快速点两下会整页放大？**

已在 2026-11-07 修复（viewport + `touch-action`）。如果仍出现，请刷新页面；若用的是很老的内置浏览器，请改用系统浏览器打开。

**Q：换电脑后列表都没了？**

数据存在浏览器本地，不同步。在原设备「导出全部列表」，把 `.json` 拷到新设备「导入列表」。

**Q：孩子能看到答案吗？**

默认隐藏，只有按住「👀 按住看单词」时才显示，可用作卡住时的提示。

## 本地开发与发布

**修改**

直接用编辑器改 `index.html` 即可，改完在浏览器里刷新验证，没有编译步骤。

**发布**

```bash
git add -A
git commit -m "改了什么"
git push
```

推送到 `main` 后约 1 分钟，GitHub Pages 会自动重新构建，线上地址随即更新，无需手动操作。

### 换电脑 / 多设备协作

源码就在仓库里，任何一台电脑 `clone` 下来都能继续改，**不需要拷贝文件或用 U 盘**。

**新电脑首次配置（只做一次）**

```bash
# 1. 安装 Git（Windows 可用 winget，或到 git-scm.com 下载安装包）
winget install --id Git.Git -e

# 2. 配置提交署名（换成自己的 GitHub 用户名与 noreply 邮箱）
git config --global user.name "YYQ208"
git config --global user.email "25290332+YYQ208@users.noreply.github.com"
git config --global credential.helper manager

# 3. 克隆仓库
git clone https://github.com/YYQ208/word-dictation.git
cd word-dictation
```

完成后直接双击 `index.html` 就能改、能预览，没有编译步骤。

**日常使用**

```bash
git pull                 # ① 开工前先拉最新版
# ② 改文件，浏览器刷新验证
git add -A
git commit -m "改了什么"
git push                 # ③ 推上去，约 1 分钟后线上自动更新
```

**网络**

GitHub 在国内不一定能直连。若 `clone` / `push` 卡住，或报 `schannel: failed to receive handshake`、`Connection reset`，给这个仓库单独配代理：

```bash
git config http.proxy http://127.0.0.1:7897     # 端口按本机代理实际端口修改
git config https.proxy http://127.0.0.1:7897
```

代理是**仓库级**配置：只对当前目录生效，不影响其他项目，也不会随仓库同步到别的电脑——每台机器各配一次即可。首次 `push` 会弹出 GitHub 授权窗口，点一次确认后由凭据管理器记住，以后不再询问。

**避免冲突**

`index.html` 是单文件，两台电脑同时改会在 `push` 时报冲突。三条规则就够：

1. 离开一台电脑前先 `push`，到另一台先 `pull`；
2. 同一时间只在一台电脑上改；
3. 万一冲突：`git pull` 会提示冲突文件，交给编辑器或 AI 合并；确认本地改动可以丢弃时，用 `git checkout --theirs index.html` 直接采用远端版本。
